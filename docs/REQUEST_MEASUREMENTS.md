# 1~11단계 정상·금지 요청 실측 절차

이 표는 학생 API의 실제 읽기 응답을 확인하는 자기 점검입니다. 운영 판정·탐지·회수·복구 기록과 41종 총공세 판정은 아닙니다. 그 결과를 대신 만들지 않습니다.

## 실행 순서

1. 자료실에서 실측 기록 만들기를 누릅니다. 로그인하지 않았으면 공개 화면·인증 없는 금지 요청만 전송합니다. 별도 `/checks.html`도 같은 익명 실측입니다.
2. 정상 보호자료 요청을 확인하려면 자료실의 기존 로그인 화면에서 직접 로그인합니다. 비밀번호·토큰을 채팅·코드·로그·제출 파일에 넣지 않습니다.
3. 현재 로그인 상태로 실측 기록 만들기를 누릅니다. `/api/request-checks`가 로그인 신원을 확인하고, 기존 기기 상태 API가 실제로 `approved: true`라고 응답한 경우에만 본인 목록·본인 메모 GET을 보냅니다. 현재 저장소의 기기 상태는 승인 미완료이므로 이 정상 보호자료 실측은 아직 실행할 수 없습니다. 승인 근거를 브라우저 값으로 만들지 않습니다.
4. 표에서 정상 보호자료 행의 HTTP 200, 금지 요청 행의 HTTP 401/403, 실제 응답 요청 ID와 확인 시각을 함께 대조합니다. 요청 ID가 응답에 없으면 미제공으로 표시합니다.
5. 정상 보호자료 허용과 금지 요청 거부가 모두 관측됐을 때만 두 결과 모두 확인이라고 표시합니다. 공개 화면·기기 상태의 200은 보호자료 허용 증거가 아닙니다. 전체 계획의 미실행 항목이 있으면 1~11단계 전체 확인은 미완료입니다.
6. 실측 기록 JSON 저장을 눌러 현재 표와 같은 공개 기록을 파일로 남깁니다. 로그인 상태 변경이나 새 실측 실행 시 이전 표와 저장 대상을 비웁니다. 이 파일은 학생 자기 점검용이며 심판 제출 묶음이나 총공세 통과 기록이 아닙니다.

## 한 표의 항목

| 단계 | 확인할 요청 |
|---|---|
| 1 | 정상 공개 화면 HTTP 200 |
| 2 | 공개 정적 파일에 메모 없음 |
| 3 | 비로그인 목록 거부, 로그인·서버 승인 후 본인 목록 허용 |
| 4 | 위조 토큰·쿼리 신원 위조 거부 |
| 5 | 인증 정보 없는 원본 API 직접 조회 거부 |
| 6 | 운영 엔진의 미등록 기기 거부: 현재 미실행 |
| 7 | 복합 이상 재확인과 재확인 뒤 정상 허용: 현재 미실행 |
| 8 | 본인 메모 한 건 허용, 다른 실계정 접근 거부. 타인 실계정 시험은 현재 미실행 |
| 9 | 운영 사건에서 정상 권한 유지·조회 폭주 회수: 현재 미실행 |
| 10 | 비로그인 복구 경로 거부, 실제 검증 복구·감사. 실제 복구·감사는 현재 미실행 |
| 11 | 비로그인 기기 상태 거부, 로그인 기기 상태 조회. HTTP 200만으로 기기 승인 완료를 뜻하지 않음 |

실측은 고정된 GET 요청만 사용하며 생성·수정·삭제·복원·회수 작업을 실행하지 않습니다. 원본 API에는 로그인 토큰·서버 키를 보내지 않습니다. 본인 메모 식별자·본문은 서버 메모리에서만 확인하고 응답 표에 넣지 않습니다. 응답 상태·본문 크기·요청 ID·확인 시각만 기록합니다.

404는 경로 미구현·대상 없음일 수 있어 거부 성공으로 처리하지 않습니다. 실제 응답을 받지 못한 요청은 network_error, 보내지 않은 요청은 not_run입니다. 둘 모두 정상·거부 실측 성공에 포함하지 않습니다.

API 응답 한 번의 `rows`와 `summary`, `confirmation`을 함께 대조해 표를 그립니다. 대조 실패·재실행 실패·로그인 세션 변경 시 이전 표를 비웁니다. 기존 운영 작전실 API의 503·원본 미연결 상태는 이 자기 점검으로 바꾸지 않습니다.

41종 시험은 `status: not_run`, `measuredCases: null`이며 41개 가상 성공 행을 만들지 않습니다. 현재 정상 보호자료 실측 조건은 기기 승인 연결이 없어 미충족입니다. `node --test test/request-checks.test.mjs`는 이 절차의 로컬 가상 검증이며 운영 시험 결과가 아닙니다.
